## Why

The plugin's scheduler (`incrementalreading.koplugin/srs_engine.lua`) is an old, heavily
simplified single-model port ("V2 with Bayesian smoothing") of an earlier SM-20 reference.
The repo now carries the canonical, binary-decoded SuperMemo 20 implementation in `sm20/`
(a tested ~4,000-line Python package: five models M1–M5, Algorithm Arena ensemble blend,
finalization pipeline, and runtime weight adaptation). Scheduling in the plugin diverges
materially from real SM-20 behavior, and every algorithm fix made in `sm20/` has to be
re-derived by hand to reach the plugin. The plugin's engine should be a faithful Lua port
of the canonical package so both stay in lockstep.

## What Changes

- Replace `srs_engine.lua`'s bespoke algorithm with a structured Lua port of the canonical
  `sm20/` package, module by module (kernel/M4, model1, model2, model3, model5, ensemble,
  weights, arena, pipeline, state). **BREAKING**: scheduled intervals will change for
  existing decks; per-card scheduling state is migrated, not preserved bit-for-bit.
- Compute next intervals the canonical way: all five models run on every review, the
  Algorithm Arena weighted blend (defaults 6/14/45/25/10) drives scheduling, then the
  finalization pipeline applies the forgetting-index factor, post-lapse curve / dispersal,
  clamping, rounding, and the minimum-growth guard.
- Adapt the Arena weights on every committed review using the decoded update rule
  (`FUN_00af40d0`), persisted as collection state.
- Map the four grade buttons to SuperMemo grades 0–5 (again→1, hard→3, good→4, easy→5)
  and pass real elapsed days since the last review (today the engine is fed the card's
  stability as elapsed time).
- Persist the full per-item state (M4 DSR state, M1/M2/M3 sub-states, prior-review slot
  stabilities, lapse markers) and collection state (M2 optimizer, M3 matrices, Arena
  weights) in SQLite, with a schema migration from the current `cards` +
  `interval_matrix`/`count_matrix` layout.
- Keep read-only grade-button previews deterministic (no dispersal jitter on preview;
  dispersal follows the canonical default of off unless configured otherwise).
- Validate the port against golden vectors generated by running the canonical Python
  package, checked by a Lua test harness runnable with plain `lua5.1`/`luajit` (no
  KOReader required).

Non-goals: porting `sm20/dat_files.py` (reads real SuperMemo `.dat` files — irrelevant to
the plugin), the opt-in R-Metric diagnostics beyond what Arena adaptation needs, and any
UI redesign beyond adapting labels/fields that referenced the old engine's state.

## Impact

- `incrementalreading.koplugin/srs_engine.lua` — replaced by the ported engine (public
  API `review`/`preview`/`formatInterval` kept in shape, results adapted).
- New `incrementalreading.koplugin/sm20/` Lua module tree mirroring the Python package.
- `incrementalreading.koplugin/database.lua` — schema migration (new per-item scheduling
  state, collection-state storage; old `interval_matrix`/`count_matrix` tables retired).
- `incrementalreading.koplugin/queue_view.lua`, `main.lua` — call sites updated (grade
  mapping, elapsed-days source, stats fields that used `stability` as an interval proxy).
- Test assets under a new `tests/` area: golden-vector generator (Python, uses `sm20/`)
  and Lua harness.
- `sm20/` itself is untouched — it remains the reference; the port must match it.
